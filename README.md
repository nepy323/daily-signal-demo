# 每日訊號圖表頁：範本與資料格式

## 這包東西是什麼

目前每日訊號是純文字推播。老闆希望改成「推播只放一條連結，點開看圖表頁」。這裡提供圖表頁的範本和資料格式，實作只需要處理兩件事：

1. 從公司系統輸出一份符合格式的 JSON。
2. 把頁面放到有網址的地方，並在推播中帶入連結。

畫圖的部分已經寫好，不需要另外開發。版面與欄位是示範，實作時功能相近即可，不必逐項一致。

| 檔案 | 用途 |
|---|---|
| `signal_page.html` | 圖表頁範本。單一檔案，不依賴任何套件或外部資源，用瀏覽器直接打開就能看到 10/20 的範例。 |
| `sample_data.json` | 範例資料（2026-10-20 的 4 檔訊號），與範本內嵌的資料相同。 |
| `demo_聊天視窗示意.html` | 示意：聊天裡出現連結，點開後從下方滑出圖表頁。僅用於向老闆說明流程，不需實作。需與 `signal_page.html` 放在同一個資料夾。 |

## 每日要做的事

1. 產出當天的 JSON（格式見下）。
2. 把 `signal_page.html` 中 `<script id="signal-data" type="application/json">` 裡面的內容，替換成當天的 JSON，另存為當天的頁面，例如 `20261020.html`。
3. 把頁面放到可公開開啟的網址，例如 `https://（網域）/d/20261020`。
4. 推播改為下方「推播文字」的格式。

## 推播文字

```
【每日訊號】10/20 13:00
共 4 檔突破訊號
https://（網域）/d/20261020
```

- 日期與時間是截斷日 K 的時間，固定 13:00。
- 檔數是當天的訊號檔數。
- 連結要帶日期。老闆回頭點舊訊息時，看到的要是當天那一份。
- 當天沒有訊號時，建議仍發訊息，內容為「【每日訊號】10/20 13:00　今日無突破訊號」，不帶連結。這樣老闆能分辨是沒有訊號還是沒有執行。

## 每張卡片顯示的內容

- TA 組別標籤。若當天漲停，另加一個紅底的「漲停」標籤，放在最前面。
- 股票名稱（代號）與產業。
- 價格與較前一日的漲跌幅。
- 成交量。
- 本益比。虧損或無資料時顯示「虧損／無資料」。
- 融資餘額，以及與前兩週平均的比較。
- 訊號時間。
- 日 K 圖：共 100 根，含價格刻度（元）、日期刻度、成交量刻度（張）。

## JSON 格式

```json
{
  "date": "2026-10-20",
  "cutoff_time": "13:00",
  "signals": [
    {
      "code": "6167",
      "name": "久正",
      "industry": "光電業",
      "groups": ["30根動能突破", "45根動能突破"],
      "price": 11.3,
      "change_pct": 9.71,
      "limit_up": true,
      "volume": 994,
      "pe": null,
      "margin": { "as_of": "2026-10-19", "balance": 2751, "avg_2w": 2877.0 },
      "signal_time": "2026-10-20 13:00",
      "bars": [
        { "d": "2026-10-20", "o": 10.3, "h": 11.3, "l": 10.3, "c": 11.3, "v": 994 }
      ]
    }
  ]
}
```

| 欄位 | 意義 |
|---|---|
| `date`、`cutoff_time` | 訊號日期與截斷時間，頁面標題顯示。 |
| `industry` | 產業別，取公司系統現有的分類。沒有就給 `null`，頁面會顯示「—」。 |
| `groups` | 該檔股票觸發的 TA 組別，與目前推播中括號內的文字相同，順序照舊。 |
| `price` | 顯示用價格。範例用的是截斷日 K 的收盤價（13:00 的價格）。突破價格若要另外呈現，可再加欄位。 |
| `change_pct` | 較前一日收盤價的漲跌幅（%），以 `price` 對前一個交易日收盤價計算。 |
| `limit_up` | 是否漲停。請用公司系統的漲停價判斷（現價是否等於漲停價），範例是依前收盤價 ×1.1 再按升降單位無條件捨去算出。 |
| `volume` | 成交量，單位為張，用發出訊號當下的截斷日 K 的量。 |
| `pe` | 本益比。`value` 為倍數，`as_of` 為該倍數的日期；虧損或沒有資料給 `null`，頁面顯示「虧損／無資料」（不要把 0 當成本益比顯示）。本益比是用收盤價算的，13:00 當下沒有當日數字，請用前一個交易日的值並標示日期。 |
| `margin` | 融資資料。`balance` 為最新可得的融資餘額（張），`avg_2w` 為其前 10 個交易日（約兩週）的平均融資餘額，`as_of` 為 `balance` 的日期。沒有融資的股票給 `null`，頁面會顯示「無融資」。 |
| `signal_time` | 訊號時間，與目前推播的「訊號時間」相同。 |
| `bars` | 日 K 共 100 根，由舊到新排列。最後一根是訊號日，前面是訊號日之前的 99 根交易日。欄位 `d` 日期、`o` 開、`h` 高、`l` 低、`c` 收、`v` 量（張）。 |

## 規格細節

- **融資資料的日期要留意。** 融資餘額在收盤後才公布，13:00 發出訊號時，當天的融資餘額還沒有。因此 `margin.balance` 要用前一個交易日的數字，並在 `as_of` 標示日期，頁面上也會顯示該日期。範例資料就是這樣處理。
- **簡圖用日 K。** 與「30 / 45 / 60 根」同一個週期。
- **最後一根是截斷日 K。** 訊號日當天的那根只到 13:00，它的高低收量都是截至 13:00 的數值，請與訊號判斷用的是同一份資料。範例資料用的是收盤後的全日資料，所以成交量會比 13:00 當下大。
- **上市未滿 100 個交易日的新股**，`bars` 有多少給多少，頁面會照實畫，不會出錯。
- **顏色採台股慣例**：紅漲綠跌。
- **頁面要能在手機瀏覽器開啟**，老闆是從 LINE 點連結進來。

## 建議的確認點

- 公司系統是否能取得每個訊號的前 99 根日 K，以及訊號日當下的截斷日 K。
- 公司系統是否有產業別與融資餘額，來源是哪裡。
- 頁面要放在哪個網址。
- 無訊號日的訊息是否照上述處理。
